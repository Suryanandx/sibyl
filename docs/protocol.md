# WebSocket protocol

The web app and the gateway talk over one WebSocket using JSON messages. All types and runtime validators live in `packages/protocol/src/index.ts`:

- `WS_EVENTS` — every event name;
- `parseClientMessage` — validates everything the browser sends before the gateway acts on it;
- `parseServerMessage` — validates everything the gateway sends before it enters browser state.

This page describes each event. When in doubt, the TypeScript types in `packages/protocol` are the source of truth.

## Connection

The browser connects to `NEXT_PUBLIC_GATEWAY_WS_URL` (default `ws://localhost:8787`). If `ALLOWED_ORIGINS` is set, the gateway rejects browser connections from other origins with HTTP 403. If `SIBYL_OWNER_TOKEN` is set, the connection URL must carry it as `?token=<value>`; otherwise the upgrade is refused and the web app shows its sign-in screen.

On connect, the gateway immediately sends `session.start` and `session.config`. If the connection drops, the browser reconnects with backoff (0.5 s, doubling up to 8 s) and re-sends the user's saved model choices with `session.update`.

Every message is a JSON object with a `type`. Most request-scoped messages carry a `requestId`, generated by the browser for typed messages and audio turns, and by the gateway for deep-brain runs. An invalid message gets an `error` reply and is otherwise ignored; messages are handled one at a time, in order.

## Typical flows

**Typed message** (with a voice brain configured, typed replies are never spoken; without one, `tts.*` events follow as in single-model mode)

```text
browser                          gateway
user.text ─────────────────────►
          ◄───────────────────── tool.started / tool.finished   (if tools are used)
          ◄───────────────────── approval.request               (write tools only)
approval.decision ─────────────►
          ◄───────────────────── llm.delta × n     (reply text)
          ◄───────────────────── ui.delta × n      (visual, if any)
          ◄───────────────────── llm.done
```

**Hands-free turn with the voice brain**

```text
vad.speech_start ──────────────►
audio.chunk × n (PCM) ─────────►
vad.speech_pause (optional) ───►   (the voice brain may start early)
vad.speech_end (+ caption) ────►
          ◄───────────────────── transcript.final   (the caption, as a placeholder)
          ◄───────────────────── llm.delta × n      (voice brain's speech)
          ◄───────────────────── tts.start / tts.chunk / tts.end
          ◄───────────────────── llm.done
          ◄───────────────────── transcript.update  (accurate transcript)
   if the voice handed off:
          ◄───────────────────── brain.start
          ◄───────────────────── brain.delta × n, ui.delta × n
          ◄───────────────────── tts.* for the gist (when you're not busy)
          ◄───────────────────── brain.done
```

The exact interleaving of `transcript.update`, `llm.*` and `tts.*` depends on which provider answers first.

## Client → gateway

### `session.start`

Optional; the gateway already starts a session on connect.

```json
{ "type": "session.start", "sessionId": "optional-id" }
```

A session is one connection. To continue a stored conversation, use `conversation.open`.

### `session.update`

Change this session's settings. Every field is optional.

```json
{
  "type": "session.update",
  "settings": {
    "voiceModel": "google/gemini-3.5-flash-lite",
    "llmModel": "anthropic/claude-sonnet-5.5",
    "sttModel": "openai/gpt-4o-mini-transcribe",
    "ttsModel": "hexgrad/kokoro-82m",
    "ttsVoice": "af_heart",
    "genUi": true,
    "speak": true
  }
}
```

Model ids must be in the gateway's catalog (and at most 200 characters); anything else is rejected with an `error`. The gateway answers with a fresh `session.config`. Models set this way count as the user's own choice and are kept when the scout updates the catalog.

### `user.text`

```json
{ "type": "user.text", "requestId": "uuid", "text": "Plan a weekend in Lisbon" }
```

Empty text is rejected. Clicks and form submissions in a visual are also sent as `user.text`, prefixed with `[UI action]`.

### `audio.chunk`

One piece of a recorded turn, base64 encoded.

```json
{
  "type": "audio.chunk",
  "requestId": "uuid",
  "chunk": "base64…",
  "mimeType": "audio/pcm;rate=24000",
  "sequence": 0,
  "isFinal": false,
  "turnMode": "live"
}
```

| Field | Meaning |
|---|---|
| `mimeType` | `audio/pcm;rate=24000` (mono PCM16) for hands-free; WebM/Opus or WAV for push-to-talk. |
| `sequence` | Non-negative integer, increasing per turn. |
| `isFinal` | Marks the last chunk of a push-to-talk turn. `chunk` may be omitted on the final message. |
| `turnMode` | `ptt` or `live`. |

A single turn may be at most 25 MB of audio.

### `vad.speech_start`

The browser's voice activity detector heard the start of a hands-free turn.

```json
{ "type": "vad.speech_start", "requestId": "uuid", "turnMode": "live", "startedAt": 12345.6, "rms": 0.04 }
```

### `vad.speech_end`

```json
{
  "type": "vad.speech_end",
  "requestId": "uuid",
  "endedAt": 15345.6,
  "durationMs": 3000,
  "reason": "silence",
  "caption": "what's the weather like in"
}
```

`reason` is `silence`, `manual` or `cancelled`. `cancelled` discards the turn. `caption` is the optional instant on-device caption (up to 4000 characters), used only as a display hint. `silenceMs` (optional) is the silence the detector waited for before ending the turn; it makes the end-of-utterance metric start at your last word.

### `vad.speech_pause` and `vad.speech_resume`

```json
{ "type": "vad.speech_pause", "requestId": "uuid", "silenceMs": 200 }
{ "type": "vad.speech_resume", "requestId": "uuid" }
```

The detector heard a short silence inside the turn but hasn't ended it yet; then, if you carry on, speech again. On a pause the gateway may start the voice brain early ([preemptive generation](voice.md#preemptive-generation)); a resume cancels that start.

### `interrupt`

Stop the current reply, for example on barge-in or the stop button.

```json
{ "type": "interrupt", "requestId": "uuid", "reason": "barge-in" }
```

### `playback.ack`

The browser finished playing an audio chunk. Accepted for diagnostics; the gateway takes no action.

```json
{ "type": "playback.ack", "requestId": "uuid", "sequence": 3 }
```

## Gateway → client

### `session.start`

```json
{ "type": "session.start", "sessionId": "uuid", "status": "ready" }
```

### `session.config`

Sent on connect, after each `session.update`, and when the model scout publishes new picks.

```json
{
  "type": "session.config",
  "catalog": {
    "voice": [{ "id": "…", "label": "…", "description": "…", "costPer100Turns": 0.02, "latencyMs": 1400, "elo": 1318 }],
    "llm": [ … ],
    "stt": [ … ],
    "tts": [{ "id": "…", "label": "…", "voices": ["af_heart"], "defaultVoice": "af_heart", "emotionTags": false }],
    "presets": [{ "id": "balanced", "label": "Balanced", "settings": { … }, "costPer100Turns": 0.13 }]
  },
  "settings": { "voiceModel": "…", "llmModel": "…", "sttModel": "…", "ttsModel": "…", "ttsVoice": "…", "genUi": true, "speak": true },
  "capabilities": { "provider": "openrouter", "genUi": true, "tts": true, "realtimeStt": false }
}
```

`voice` and `presets` are present only when configured. `costPer100Turns`, `latencyMs` and `elo` come from the model scout. Server-side request parameters are never included.

### `transcript.partial`

A provisional transcript while you are still speaking (single-model hands-free mode).

```json
{ "type": "transcript.partial", "requestId": "uuid", "text": "what's the", "sequence": 1, "isStable": false }
```

### `transcript.final`

The user's words for a turn. With the voice brain, this is the instant caption (possibly empty) sent as a placeholder.

```json
{ "type": "transcript.final", "requestId": "uuid", "text": "What's the weather like in Porto?" }
```

### `transcript.update`

The accurate transcript for a turn that has already started; replaces the caption.

```json
{ "type": "transcript.update", "requestId": "uuid", "text": "What's the weather like in Porto?" }
```

### `turn.metrics`

Timings of one spoken reply, with LiveKit Agents' metric names ([voice.md](voice.md#latency-metrics)), on the WebSocket and the LiveKit path. Durations in ms; any may be missing.

```json
{
  "type": "turn.metrics",
  "requestId": "uuid",
  "metrics": { "transport": "websocket", "eouDelayMs": 300, "transcriptionDelayMs": 1400, "llmTtftMs": 1350, "ttsTtfbMs": 420, "e2eLatencyMs": 2400, "preemptive": true, "voiceModel": "qwen/qwen3.8-omni-flash", "ttsModel": "assemblyai/assemblyai-tts-1" }
}
```

### `turn.merged`

You kept talking after a short pause, before Sibyl answered aloud. The earlier turn `mergedRequestId` is folded into `requestId` and answered once.

```json
{ "type": "turn.merged", "requestId": "uuid-2", "mergedRequestId": "uuid-1" }
```

### `llm.delta` and `llm.done`

Streamed spoken text of the reply, then its end.

```json
{ "type": "llm.delta", "requestId": "uuid", "delta": "[warmly] Sure, " }
{ "type": "llm.done", "requestId": "uuid", "reason": "stop" }
```

`reason` is `stop`, `interrupted`, `error` or `ignored` (the turn had no speech meant for Sibyl).

### `ui.delta`

Streamed `openui-lang` source for the visual of `requestId` (a reply or a deep-brain run). See [generative-ui.md](generative-ui.md).

```json
{ "type": "ui.delta", "requestId": "uuid", "delta": "root = Card([" }
```

### `brain.start`, `brain.delta`, `brain.done`

A deep-brain run started by the voice brain.

```json
{ "type": "brain.start", "requestId": "brain-uuid", "parentRequestId": "uuid", "task": "Compare…", "model": "z-ai/glm-5.3-flash" }
{ "type": "brain.delta", "requestId": "brain-uuid", "delta": "The train is cheapest…" }
{ "type": "brain.done", "requestId": "brain-uuid", "reason": "stop" }
```

`requestId` identifies the run; its `ui.delta` and `tts.*` events use the same id. `reason` is `stop`, `interrupted` or `error`.

### `tts.start`, `tts.chunk`, `tts.end`

Spoken audio for a reply, a segment at a time.

```json
{ "type": "tts.start", "requestId": "uuid", "voice": "af_heart", "format": "mp3", "mimeType": "audio/mpeg" }
{ "type": "tts.chunk", "requestId": "uuid", "sequence": 0, "segmentIndex": 0, "chunk": "base64…", "mimeType": "audio/mpeg", "isFinal": false }
{ "type": "tts.end", "requestId": "uuid", "reason": "stop" }
```

Each chunk is a complete, decodable audio file for one segment. The browser plays them in `sequence` order on a single timeline. Raw PCM from a speech model is wrapped as WAV by the gateway.

### `error`

```json
{ "type": "error", "requestId": "uuid", "message": "Voice model is not allowed: …", "scope": "llm" }
```

`requestId` and `scope` are optional. `scope` is `tts`, `stt` or `llm`. `tts` errors are not fatal: text and visuals keep streaming, only speech stops.

## Conversations

Conversations are stored on the gateway. The browser lists, opens and deletes them with these events.

### `conversations.request` → `conversations.list`

```json
{ "type": "conversations.request" }
{ "type": "conversations.list", "items": [{ "id": "c1", "title": "Weekend in Lisbon", "updatedAt": 1762646400000 }] }
```

### `conversation.open` → `conversation.state`

Start a new conversation (no id) or continue a stored one. The gateway restores its context, so the next message carries on with full history.

```json
{ "type": "conversation.open", "conversationId": "c1" }
{
  "type": "conversation.state",
  "conversationId": "c1",
  "title": "Weekend in Lisbon",
  "messages": [
    { "id": "m1", "role": "user", "content": "Plan a weekend in Lisbon", "requestId": "r1", "source": "text", "createdAt": 1762646400000 },
    { "id": "m2", "role": "assistant", "content": "Here's a relaxed plan…", "requestId": "r1", "ui": "root = Card([…])", "createdAt": 1762646405000 }
  ]
}
```

Assistant messages may carry `ui` (the visual's source), `kind: "brain"` with `task` and `model` for deep-brain results, and `steps` listing tool calls with their status.

### `conversation.delete`

```json
{ "type": "conversation.delete", "conversationId": "c1" }
```

## Tools and approvals

### `tool.started`, `tool.finished`

A tool call made by the deep brain during run `requestId`.

```json
{ "type": "tool.started", "requestId": "brain-uuid", "callId": "call-1", "toolName": "web_search", "title": "Searching the web" }
{ "type": "tool.finished", "requestId": "brain-uuid", "callId": "call-1", "status": "ok", "summary": "5 results" }
```

`status` is `ok`, `error` or `declined`.

### `approval.request`

A write tool is waiting for the user.

```json
{
  "type": "approval.request",
  "approval": {
    "id": "a1",
    "runId": "brain-uuid",
    "conversationId": "c1",
    "toolName": "crm__create_contact",
    "title": "Create contact",
    "summary": "Create a contact named Ana Lima in the CRM.",
    "details": [{ "label": "email", "value": "ana@example.com" }],
    "createdAt": 1762646400000,
    "expiresAt": 1762647000000
  }
}
```

`details` is already shortened and has secrets masked by the gateway.

### `approval.decision`

```json
{ "type": "approval.decision", "id": "a1", "decision": "approve", "remember": "conversation" }
```

`decision` is `approve` or `decline`. `remember: "conversation"` stops asking for this tool for the rest of the conversation.

### `approval.resolved`

```json
{ "type": "approval.resolved", "id": "a1", "status": "approved" }
```

`status` is `approved`, `declined` or `expired`.

## Usage and budgets

### `usage.request` → `usage.update`

```json
{ "type": "usage.request" }
{
  "type": "usage.update",
  "usage": {
    "todayUsd": 0.042, "monthUsd": 1.37, "sessionUsd": 0.011,
    "dailyBudgetUsd": 1, "monthlyBudgetUsd": 20,
    "byFeature": { "voice": 0.004, "brain": 0.006, "tts": 0.001 },
    "economyMode": false
  }
}
```

`economyMode` is true when spending is close to a cap and cheaper models are in use.

### `budget.blocked`

A model call was refused because a budget is used up.

```json
{ "type": "budget.blocked", "requestId": "uuid", "scope": "daily", "message": "Today's budget is used up…" }
```

`scope` is `daily`, `monthly`, `routine_run` or `routine_daily`.

## Changing the protocol

- Add the type and the validation to `packages/protocol` together. Validate everything the browser sends.
- Don't change the meaning of an existing event; add an optional field or a new event instead.
- Add a gateway test for the new behaviour and update this page.
