The products

Five products, one install.

Each one does the job of a tool you would otherwise pay for per seat. They share one sign-in, one set of permissions, one approval flow and one budget, so they work together: an agent joins your meeting, a deck comes from your knowledge, an image you made goes into a chat.

  • Sibyl Studio

  • Sibyl Agents

A new product joins every week. Next: Sibyl Phone, which ships once it has been tested on a real phone line.

One install for talking, meeting, making and getting things done — on ground you control.

Sibyl answers in voice or text, with charts, tables and forms you can click. It searches your own files, works in your Google, Microsoft and Slack accounts, makes slide decks, and runs agents you design. Every action that sends, creates, deletes or spends shows you an approval card first.

It is a web app and a small gateway that keeps every key, enforces every permission and stores everything in SQLite on your server.

Why Sibyl

Helping shape AI that belongs to everyone.

Freedom

Your server, your data. Run it on a laptop, a home server or your company's cloud. Choose any model through one key and switch whenever you like. Everything lives in one folder you can back up, export or delete.

For everyone

AI should be something people own and steer, not something they rent and hope stays the same. Sibyl is open and inspectable: read the code, change it, extend it with skills, plugins and MCP tools.

You stay in control

01 Chat

Talk or type

Type and you get a written reply with visuals. Tap the mic and it becomes a live conversation: a fast voice brain answers out loud in a second or two and hands careful work to a deep brain, whose short summary is spoken while the details appear on screen.

Talk over it and it stops in about half a second. Old chats pick up where they left off.

Voice docs →

Visual answers

Replies can include charts, tables, plans, option cards and forms, with their sources underneath. Buttons and forms send your choice straight back to Sibyl, so a question can turn into a short back-and-forth.

Generative UI docs →

Side panel

A panel on the right of the chat keeps the work beside the conversation: an agent's computer while it browses, the media it made, slide decks, visuals and files. Close it and the chat has the whole width again.

Side panel docs →

Memory

Sibyl can remember short facts about you across chats, and you can see and remove them in Settings. Memory is personal: each person has their own list in each workspace, and nobody else sees it. One switch turns it off.

Memory docs →

02 Agents

Agents you build

Give an agent a name, a face, its own voice and personality, and instructions. Choose what it may use — everything I can use, or a controlled list of tools, connections, knowledge and skills — and how it acts: ask me first, act, then tell me, or fully autonomous. High-risk actions always ask.

After a task an agent can propose a better skill. You approve it, or let it save on its own, and you can roll it back. Each agent can have its own daily and monthly budget.

Agents docs →

Agent computers

An agent can have its own computer: a real browser in a sandbox on your server, with a folder for files. Watch it work live, look back at every step, and stop it at any time.

Reading and browsing just happen. Sending a form or signing in follows the agent's autonomy, and buying anything always asks you first. Private and local addresses are blocked.

Agent computers docs →

Agents in Slack and Teams

Put an agent in a Slack or Microsoft Teams channel. It answers when someone @mentions it, then keeps going in the thread, with the same instructions, budgets and approvals it has in Sibyl. With ask me first, a write waits for approval in your Inbox and the agent says so in the thread.

Slack and Teams docs →

03 Meetings

Meetings

Calls where people and agents meet together. Start one now, schedule it, or pick an event from your connected calendar. Agents join as participants who speak when named, or as silent note-takers. Sibyl keeps the transcript, writes the summary as you talk and finds the action items.

Afterwards each meeting has its own page with notes, transcript, actions and an Ask AI box. Guests can join by link once the host lets them in.

Meetings docs →

Calls and phone

Meetings and calls run on the optional LiveKit layer, which you also host yourself: WebRTC voice, several people and agents in one room, each agent with its own voice and avatar. Bring a live stream into a room and an agent takes notes.

Phone lines are Coming soon: they ship once they have been tested on a real line. Call recordings come with Agent Serve.

Realtime docs →

04 Spaces

Slides

Ask in chat or open Spaces → Slides to make a deck from a prompt, your files or your connected data. You approve the build on a card that says roughly what it costs, edit the deck yourself, and export PowerPoint or PDF.

Slides docs →

Media

Make images, video and audio from chat or from Spaces → Media. Point at earlier work with @ references, and tune each model's own settings. What you make lands in the Media tab and in the chat's side panel.

Media docs →

05 Library

Knowledge from any file

Knowledge bases take PDF (scanned pages too), Word, Excel, PowerPoint, OpenDocument, e-mail, EPUB, code, images, whole folders and ZIP archives, plus web pages and pasted notes. Sibyl searches them and cites what it used, down to the page or slide.

Knowledge docs →

Skills and plugins

A skill is an instruction pack — "how we write release notes" — that Sibyl loads only when a request needs it. Write one in the app or import a SKILL.md, a folder or a zip, with versions you can restore. Plugins bundle skills, tools and settings into one install.

Skills docs →

Integrations

Native connectors for Google Workspace (Gmail, Calendar, Drive, Docs, Sheets), Microsoft 365 (Outlook, Calendar, OneDrive, Excel, Teams) and Slack. Anything else connects through MCP. HubSpot and Salesforce come with Agent Serve. Every action that changes something shows an approval card first.

Integrations docs →

06 Automations

Routines and monitors

Routines run on a schedule. Monitors watch Gmail, Outlook, Calendar, files, CRM records, web pages or RSS feeds and tell you, or start a task, when a plain-language condition is met — "tell me when a deal over $50k moves to Negotiation". Only new things fire.

Everything lands in the Inbox behind the bell at the top of the rail, with approvals for anything that changes data.

Monitors docs →

07 Settings and control

Getting started

A short setup walks you through your model key, a style, your tools, a first agent, knowledge and your team. Optional steps have Skip, and Finish later picks up where you were, on any device. Until you are done, a Getting started ring in the rail ticks each item off when you really do it.

On hosted Sibyl (coming soon), sign-up with Google, Microsoft or e-mail leads straight into the same setup.

Getting started docs →

Secrets vault

Keys and tokens you add are encrypted on your server and only ever sent to the hosts you allow. When Sibyl needs a key, it asks in a secure box inside its reply; the model never sees the value, and tool results are scrubbed before it reads them.

Secrets docs →

Models and costs

A model scout picks models from OpenRouter's live catalog by price, benchmarks and measured speed. Choose a preset and see what 100 typed messages and 100 spoken turns cost. Every call is metered, daily and monthly budgets stop spending before it happens, and near a cap Sibyl moves to cheaper models.

Bring your own OpenRouter key. On hosted Sibyl you will also be able to buy AI credits instead.

Models and costs docs →

Teams and admin

Workspaces, invitations, roles (owner, admin, member, viewer), two-step sign-in and budgets for the organisation and each workspace are all free and open source. Admin sits inside Settings for owners and admins. Agent Serve adds custom roles, policies, an audit log, SSO and SCIM.

Admin docs →

Privacy and self-hosting

Conversations, files, knowledge, memory and usage stay in one data folder on your server. Your words go only to the model provider you chose through OpenRouter, and to connected apps after an approval. Keys never reach the browser, and logs redact credentials, audio and messages.

One docker compose up runs it. Profiles add realtime calls, phone and agent computers.

Get started

Running in a few minutes.

You need an OpenRouter API key. Set OPENROUTER_API_KEY in .env, then open http://localhost:3000 and create the owner account.

git clone https://github.com/Suryanandx/sibyl.git && cd sibyl && cp .env.example .env && docker compose up --build

The line copies .env.example to .env; add your OPENROUTER_API_KEY there and run docker compose up again if it stopped. Starts the web app on port 3000, the gateway on 8787 and the Slides engine.

git clone https://github.com/Suryanandx/sibyl.git
cd sibyl
corepack enable
corepack pnpm install
cp .env.example .env        # then set OPENROUTER_API_KEY
corepack pnpm dev

Needs Node.js 22.13 or newer. pnpm comes through corepack, which ships with Node.
